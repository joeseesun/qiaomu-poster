# 从真实失败中提炼的回归

这些是2026-10-27 GEO批次发现的问题，不是给所有品牌锁定同一审美。

| 真实问题 | 根因 | 修复与验收 |
|---|---|---|
| GEO与大会相隔太远 | 把单一活动名当成左右两个栏位 | 同一视觉组，测量组间隙并看实际字面；回归fixture模拟大gap |
| 小头像贴片 | 先套模板再把Logo塞角落 | 头像去底成为主体或自然署名；深浅背景看接缝 |
| 换色但结构相同 | 没有每品牌隐喻与拓扑计划 | 先列构图与主体关系，再并排检查；声明重复检查不是美学判定 |
| GAIDN深蓝大方块 | 背景色接近但不相同 | 真实透明去底；复查环线连续性与字形 |
| Yangyi头像白方块盖住轨道 | 不透明源图覆盖下层 | 透明提取，导出图里轨道连续 |
| 角色身体水平切口 | 抠图只是消背景，没有构图衔接 | 斜向前景遮挡或末端小范围渐隐 |
| 橘AI黑笔迹压黑文字 | 主视觉和文案没有安全区 | 主视觉缩小/上移，实际可见间距再核对 |
| GEO衬线配大会粗黑 | 按字号而非字形选择字体 | 对齐笔画对比、视觉重量和字面高度 |
| 二维码变白块 | 截图时图片尚未解码 | 等fonts.ready与img.decode；最终PNG解码 |
| 旧报名链接遗留 | 用户更新需求但素材没更新 | 清单锁定最新URL，所有最终PNG独立核验 |

脚本能发现标题间距/失载/事实文字/QR和声明层结构重复，不能可靠自动发现所有遮挡、身份变化和艺术质量。目视记录与机器报告分开保存。不要把“18张技术检查通过”写成“18张已获客户认可”。

## 自定义字体别名被浏览器忽略

实际复核发现 `@font-face{font-family:Serif}` 使用了通用字体族保留名称，中文出现黑体回退；仅 `document.fonts.ready` 无法证明选中了预期字体。改用唯一别名 `PosterSerif`，重新渲染全部案例并目视确认中文宋体的笔画。该案例说明自动布局通过仍需看实际字形。
